# University requirements: implemented versus still to integrate

This matrix is a requirements map, not a certification or a claim that a university needs every row. The institution's operational boundary and reporting purpose decide applicability.

| Area | This release | What is not automatically done |
| --- | --- | --- |
| Campus operations | Campus/building/department owners, ten source types, 11 facility labels, eight-category screening | Physical asset discovery, CMMS synchronization and proof that all sources are registered |
| DG, boiler, kitchen | Reviewed fuel quantities; stock/meter methods; gas/GWP factors | Automatic calorific values, fuel density and all plant-specific engineering conversions |
| Fleet | Controlled-vehicle fuel pathway | Automatic distance-to-fuel, telematics, contracted-fleet Scope classification |
| Refrigerants | Direct loss, stock/equipment balance, attested leak-replacement top-up | Automatic refrigerant blend identification or purchase-as-leak inference |
| Lab/hospital gases | Named reviewed GHG mass releases | Automatic clinical consumption-to-atmospheric-release fractions |
| Campus farm / wastewater | Generic activity x reviewed process factor | Full IPCC livestock/soil/wastewater/land accounting and uncertainty models |
| Electricity / district energy | Gross imports, delivered kWh, location and market alternatives | Steam enthalpy, CHP allocation or parent/submeter auto reconciliation |
| Renewables | Retained evidence, local serial uniqueness, beneficiary/period/quantity checks, independent review | Registry verification, global anti-double-claim checks, automatic credits or offsets |
| University data collection | Existing 22 and optional ten additional KPI definitions, evidence, owners and review | Complete STARS/BRSR/CSRD forms, automatic scoring or certification |
| Water, waste, dining | Existing university KPIs and selected Scope 3 categories; added harvested rainwater KPI | Every waste-treatment, food LCA or water scarcity methodology |
| Governance | Source completeness, corrective actions, deadlines, independent close, audit, period locks | SSO/MFA, automatic email escalation, procurement approvals outside this app |
| Reporting | Frozen independently approved JSON/CSV/HTML, source/factor/evidence traceability | External assurance, legal sign-off, server-side DOCX/PDF rendering |
| Reduction planning | Existing initiatives and fixed-method LOCATION/MARKET targets | Verified causality, automatically credited project savings or net-zero certification |
| Integration | Existing private uploads, scanner/worker adapter and CSV | AI OCR, ERP, IoT, energy supplier API, automatic official factor feeds |
| Product operations | Existing infrastructure foundation plus bounded carbon APIs | Verified production capacity, disaster recovery, billing, account SSO or a penetration-test certificate |

Existing academic, research, student/staff and governance KPIs remain. Sensitive student/employee health, demographics, educational records or personal travel details should not be added merely to make this list longer; use minimal aggregate data and an institution-approved privacy design.

The recommended first operational rollout is one campus, a reviewed reporting period, a small complete source register and real anonymized evidence. Acceptance must demonstrate an end-to-end reviewed inventory before wider deployment.
