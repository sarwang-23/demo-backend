# Mandatory staging acceptance gates

This release has no verified live-user capacity number or production approval. Complete these gates with representative university data before external use.

1. Build the runtime image from the supplied source. Generate/review Node and Python dependency lockfiles and software bill of materials, pin base-image/OS package policy, run current vulnerability checks and deploy patched parser/Poppler/scanner versions. Registry access was unavailable during authoring.
2. Run migrations 001-004 on a disposable PostgreSQL `_test` database with separate owner, API and worker roles. Execute `npm run test:integration`, `npm run test:university:postgres`, `npm run test:carbon:postgres` and `npm run test:ingestion:postgres`. Check RLS, composite constraints, immutable receipts, transaction rollback, retries and concurrent duplicate prevention. The new PostgreSQL suite is included but was not run here.
3. Send real XLSX/CSV/PDF bytes through private versioned S3 storage and ClamAV, then worker extraction. Test scan failure, malicious input, job retry/fencing, expired lease, object corruption, partial upload, crash recovery, quotas, duplicate original and redacted logs. No scan bypass is acceptable.
4. Restrict parser process/container network access and resource use, protect temporary storage, monitor worker queue lag, review OOXML/PDF parser isolation and fuzz-test malformed files. Process separation and timeouts are not a complete sandbox.
5. Run native browser navigation with the deployed CSP, HTTPS and reverse-proxy settings. Check real file input/download, refreshed sessions, desktop/mobile behavior, accessibility, role restrictions and UI error recovery. Delivery UI checks used a DOM harness/local HTTP bridge, not native navigation/CSP.
6. Rehearse backups and restores of database plus exact original object versions. Verify restored mapping history, source provenance, imported receipts, target drafts and approved reports. Decide retention, deletion approvals and legal requirements with the university.
7. Measure representative concurrent imports and worker throughput, memory/CPU/temp-storage, DB lock waits and request deadlines. The bounded 500-row/100-row requests are safeguards, not proven performance targets. Avoid increasing limits without measurements.
8. Business sign-off: source ownership, reporting boundary, applicable factor provenance and validity, stock-vs-consumption semantics, meter quantities, approved correction flows, invoice numbering conventions, duplicate cases, financial-vs-physical quantities and period close.
9. Resolve unsupported input layouts explicitly; do not advertise universal AI parsing. Scans still need manual fields unless a separately assessed OCR provider is integrated with evidence-based human review.
