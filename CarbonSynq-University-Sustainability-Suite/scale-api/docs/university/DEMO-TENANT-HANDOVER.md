# Synthetic demo tenant: seeding and handover runbook

This runbook reproduces the synthetic leadership demo dataset in an **isolated rehearsal tenant**. Every seeded record is
labelled `SYNTHETIC DEMO`, the factor registry version labels are `DEMO-*`, and no figure is an official published factor or a real
university measurement. Independent assurance or compliance certification is never claimed.

## 1. What the seed script does

`scale-api/scripts/seed-university-demo.mjs` (npm alias `npm run university:seed-demo`) writes, in 15 resumable phases:

| Phase | Content |
| --- | --- |
| `1-identity` | Admin/reviewer sessions, two ENTRY data-entry users, one LEADERSHIP user, Main/North/South campuses, buildings, departments, three reporting periods |
| `2-evidence` | Six ClamAV-scanned evidence files (two invoice PDFs, diesel log, waste note, two KPI meter logs) |
| `3-catalog` | 22 university KPI definitions + 10 supplementary carbon indicators |
| `4-factors` | 19 approved university activity factors + 2 core grid/diesel factors |
| `5-core-console` | Core activity ledger for both closed years, including two invoice-confirmed electricity entries |
| `6-historical` | 15-category Scope 3 screening per period, then 20 calculated university emissions per closed year |
| `7-collections` | KPI collection tasks with maker-checker submissions for both closed years (100% complete) |
| `8-reports` | Period locks, two independently approved inventory snapshots, 25%-reduction target, three initiatives |
| `9-carbon-ledger` | 7 Scope 1/2 sources, 8 approved carbon factors, one PPA instrument, approved DUAL-mode boundary |
| `10-carbon-records` | 16 calculated carbon records across the seven sources (electricity balance/meter, diesel, refrigerant, steam) |
| `11-current-period` | 13 Scope 3/supplemental emissions for FY2026-27 plus deliberately open KPI tasks |
| `12-actions` | One closed HIGH corrective action, one still-open MEDIUM action |
| `13-collaboration` | Two supplier requests (one approved, one deliberately open) and an approved materiality assessment |
| `14-planning` | Approved PCF screening study and a dry-run emissions CSV import preview |
| `15-reporting` | Overview, carbon dashboard, target progress, five insight questions, knowledge search, commuting estimate, report export |

Phases are idempotent: existing records are matched by external key, code or title, and object state is cached in
`%TEMP%/carbonsynq-demo-evidence/seed-state.json` (override with `DEMO_EVIDENCE_DIR`). Re-running the whole script creates nothing twice.

## 2. Create the rehearsal tenant

Preferred (host run, so you control the demo passwords):

```bash
# from scale-api/, with DATABASE_OWNER_URL already in .env
ADMIN_PASSWORD='Demo@12345678' REVIEWER_PASSWORD='Review@123456' node --env-file=.env scripts/provision.mjs
```

Container alternative (passwords are generated and printed once):

```bash
npm run neon:provision   # compose forwards only TENANT_NAME/ADMIN_EMAIL/REVIEWER_EMAIL
```

Either way the command prints `tenantId`, admin/reviewer credentials, `campusId` and `periodId`. Keep this tenant separate from any
real installation. `provision.mjs` creates an empty tenant; the seed script only adds labelled synthetic demo data and never
provisions, deletes or resets a tenant.

## 3. Seed

```bash
DEMO_TENANT_ID=<printed tenant id> npm run university:seed-demo
```

Environment knobs: `DEMO_TENANT_ID` (required), `DEMO_BASE` (default `http://localhost:5000`), `DEMO_ADMIN_EMAIL`,
`DEMO_REVIEWER_EMAIL`, `DEMO_ADMIN_PASSWORD`, `DEMO_REVIEWER_PASSWORD`, `DEMO_EVIDENCE_DIR`.

Useful for debugging a single failure:

```bash
DEMO_TENANT_ID=<id> npm run university:seed-demo -- --phase=9-carbon-ledger
```

Two operational notes:

- `POST /api/v2/auth/login` is limited to 30 attempts per IP per 15 minutes. Sessions are cached in the state file, and expired
  sessions are refreshed transparently; if you hit `RATE_LIMITED`, wait for the window instead of restarting the script repeatedly.
- Document uploads are deduplicated per tenant by content hash, so the second invoice confirmation uses a generated byte-distinct
  copy of `samples/sample-electricity.pdf`. Never upload the same file twice expecting two documents.

## 5. Expected verified state

Re-check the tenant at any time with the read-only verifier (uses the cached session from the seed state file):

```bash
npm run university:verify-demo
```

| Check | Expected |
| --- | --- |
| Periods | `FY2024-25` LOCKED, `FY2025-26` LOCKED, `FY2026-27` OPEN |
| Documents | 6 scanned `CLEAN`, invoice PDFs `LINKED`, remaining evidence `REVIEW_REQUIRED` |
| Inventory reports | 2 `APPROVED` snapshots, integrity verified, comparable boundaries |
| Carbon boundary | `APPROVED`, revision 1, `scope2_mode: DUAL`, readiness `ready: true` with one lower-severity finding |
| Carbon records | 16 `CALCULATED`; Scope 1 38,970 kg CO2e; Scope 2 location 5,755,000 kg; market 6,112,667 kg |
| University emissions | 53 `CALCULATED` (20 + 20 historical, 13 current period) |
| Scope 3 screening | 45 rows: 15 categories x 3 periods |
| Collections | 43 tasks: 35 complete, 8 open in FY2026-27 |
| Corrective actions | HIGH closed, MEDIUM open |
| Supplier requests | one APPROVED, one OPEN (deliberate) |
| Materiality | APPROVED after 6 responses |
| PCF study | APPROVED |
| Target progress | comparable baseline, ~20% observed reduction against a 25% requirement, threshold not yet met |

Scope 2 market-based total is deliberately **higher** than location-based: the residual grid mix factor (0.78) is dirtier than the
grid average (0.71), and only 300,000 kWh are covered by the PPA. Use it to discuss instrument quality and residual-mix honesty
rather than to claim a market-based reduction.

## 6. Suggested 10-minute walkthrough

1. **Overview** – switch periods; show Scope 1/2/3 split, supplemental student commuting/travel, 38% collection completion in FY2026-27.
2. **Collection** – open the 8 open tasks, assign an ENTRY user, submit a value, approve it as the reviewer (maker-checker separation).
3. **Evidence and invoice confirmation** – open a `REVIEW_REQUIRED` invoice PDF, show the manual quantity confirmation and the calculated result.
4. **Scope 1/2 ledger** – boundary revision, source coverage per campus, dual Scope 2 totals, PPA instrument quality checks, residual-mix fallback.
5. **Corrective actions** – the closed HIGH action and the still-open MEDIUM finding that keeps readiness `ready: true` with a warning.
6. **Collaboration** – supplier capability token, portal submission, the deliberately open second request, materiality aggregate.
7. **Targets** – show that an approved initiative never reduces inventory; progress comes only from comparable approved reports.
8. **Reports and insights** – export JSON/CSV/HTML, then the five insight questions with their database citations.

Wording that stays accurate: "integrated source-code release candidate, local tests pass, infrastructure acceptance still required,
figures are internally reviewed with no independent assurance claim."

## 7. Reset and hygiene

- The script never deletes data. To rebuild from scratch, provision a **new** tenant and seed that; leave the old rehearsal tenant for
  audit or drop it through the normal database backup/restore procedure.
- `seed-state.json` holds session tokens. Treat it as a secret file, keep it out of version control, and delete it when the rehearsal ends.
- Never commit `.env`, Neon URLs or database credentials. `scripts/check-neon-env.mjs` verifies the environment without printing secrets.
