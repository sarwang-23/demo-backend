# University leadership rehearsal (Hinglish)

## Pehle setup aur boundaries

`README-UNIVERSITY-FIRST.md` se new stack start karo. New URL `http://localhost:8080/university` hai; root `npm start` purana SQLite demo hai. Naya university module isi existing PostgreSQL scale-api mein integrated hai. Old accounts/data automatic Neon ya SQLite se import nahi hue hain.

CEO meeting se pehle real staging stack par end-to-end rehearsal karo. New tenant mein zero data dikhna sahi hai: backend impressive totals invent nahi karta. Sirf isolated rehearsal tenant mein clearly labelled synthetic records use karo. Iss ZIP ka preview screenshot synthetic test fixtures ka hai, kisi real university ka result nahi.

## 8-10 minute walkthrough

**1. University overview.** Reporting period select karo. Primary inventory, separate student commuting/travel, pending collections, approved KPI values aur factor/evidence traceability dikhao. Empty figures ka matlab missing data ho sakta hai, zero emissions nahi. Leadership role read-only hai.

**2. Data collection.** Admin se 22 KPI definitions install karo. Electricity/water/waste ke saath student/staff FTE, floor area, training, sustainability courses aur governance indicators dikhao. Ek source/meter task assign karo. Assignee aur reviewer alag users hone chahiye.

**3. Manual entry and invoice evidence.** Evidence screen ya core console se original invoice upload karo. Real scanner complete hone do. Quantity aur unit manually verify karo; invoice ki money amount ko consumption mat banao. Assigned user draft submit kare, doosra reviewer approve kare. Approved source record se dashboard ka number trace karo. New suite mein real OCR engine nahi hai.

**4. Scope 3 and accounting boundary.** Dining/procurement, waste, travel aur employee commute category records dikhao. Factor source/version aur method dikhao. All-15-category screening mein unassessed/excluded categories explain karo. Student commuting is product mein supplemental hai; institutional accounting policy reviewer se decide karni hai.

**5. Supplier and stakeholder collaboration.** Supplier request create karke private invitation issue karo. Portal mein token paste karna aur typed answers submit karna dikhao. Token screen close hone ke baad dobara reveal nahi hota. Materiality mein minimum five responses se pehle aggregate suppression dikhao; survey exploratory hai, formal certification nahi.

**6. Plans versus achieved reductions.** Solar/LED/fleet project ka owner, dates aur planned saving record dikhao. Explain karo ki plan approve hone se actual emissions number reduce nahi hota. Approved comparable inventory reports se target progress calculate hota hai.

**7. Reports and traceable insights.** Pending work resolve, period lock, report snapshot aur separate approval dikhao. JSON/CSV/printable HTML export show karo. Evidence and factor provenance preserve hote hain. Insights five supported questions ke database facts hain, AI-generated claims nahi.

**8. Optional PCF.** University research/procurement screening use case dikhao; factory production workflow ko university ki mandatory need mat bolo. Functional unit, allocation aur omitted stages visible hain. PCF result main inventory mein double-count nahi hota.

## Meeting mein accurate wording

"Yeh integrated source-code release candidate hai. Local tests pass hue hain. Real staging deployment, file scanning, tenant isolation and backup restoration ko acceptance testing se pass karna hai. Figures internally reviewed hain; independent assurance ya compliance certification ka claim nahi hai."

UI/API Studio mein nested questionnaires, BOM lines aur complex bodies ke liye JSON fields hain. Har advanced workflow ka bespoke drag-and-drop editor nahi banaya gaya. Source/API contract included hai so the product team can extend those screens without inventing backend features.
